# Правила сопровождения HH AutoApply

Перед изменениями прочитайте этот файл и `docs/PROJECT_STATE.md`, проверьте текущую ветку, upstream и состояние GitHub. Сохраняйте работающие функции. Используйте ветки и небольшие коммиты. Запускайте CI-проверки локально и открывайте PR в main. Обновляйте CHANGELOG и PROJECT_STATE при изменениях поведения, инфраструктуры или результатов проверки.

## Продукт

Персональный русскоязычный Telegram-помощник соискателя. Основная платформа управления — iPhone через Telegram Mini App и чат с ботом. Хостинг Bothost, одна реплика, Python 3.12, `bot.py`, GitHub main и постоянный `DATA_DIR`. Прежние 512 МБ RAM, 1 ГБ диска, Pterodactyl и Python 3.14 относятся к исторической инфраструктуре. Проверяйте квоты тарифа и Runtime перед утверждениями о текущем хостинге.

Не используйте HH API. Локальный Chromium Headless Shell запускается только по явной настройке владельца. Авторизация выполняется владельцем на HH через приватную ссылку с таймаутом. Бот подтверждает вход по личным показателям кабинета HH, личному списку резюме или кнопке редактирования конкретного резюме. После подтверждения сразу сохраняет сессию, а загрузку резюме выполняет отдельно. Бот импортирует только профессиональные разделы выбранного резюме и останавливается при CAPTCHA, блокировках или неизвестном результате. Не обходите антибот-защиту, не используйте прокси и режимы скрытности, не передавайте пароли, SMS-коды, cookies или токен ссылки входа в логи. Браузерный режим требует сквозной проверки перед эксплуатацией. Ручной сценарий остаётся доступен.

По умолчанию финансовый менеджер, Москва, 150000 RUB, формат и график любые, общий балл Groq от 80%, совпадение по навыкам для автоотклика от 80%, лимит до 100 откликов в сутки, интервал 30 минут, Europe/Moscow, дедупликация по ID. Смежные запросы настраиваются отдельно. Подтверждение черновика — режим по умолчанию.

## Безопасность и реализация

- Проверяйте `OWNER_ID` и личный чат на каждом входе Telegram. Сохраняйте тексты и настройки только вне GitHub. Условия тарифа определяют наличие Volume. Bothost документирует точку монтирования `/app/data`. `PERSISTENT_STORAGE=true` только подтверждает проверенный диск. При временном диске явно показывайте риск потери состояния.
- Groq использует `openai/gpt-oss-120b` по умолчанию и поддерживает `GROQ_MODEL`. Валидируйте структурированные результаты. Входное описание считается недоверенным текстом. Удаляйте типовые контакты и передавайте минимум профессиональных сведений после согласия. Автоотклик HH использует письмо, составленное из проверенных дословных выдержек, которые Groq выбрал для вакансии. Повторно проверяйте письмо, резюме и текущий порог перед отправкой.
- Вход HH и Mini App используют HTTPS-интерфейс Bothost. Для приватных маршрутов Mini App проверяйте подпись и срок действия Telegram initData и OWNER_ID. Состояние HH хранится в DATA_DIR. Не активируйте платные сервисы и не отправляйте тестовые отклики без разрешения.
- Встраивайте поиск других сайтов через их общедоступные или документированные интерфейсы. Изолируйте сбои источников. Для Mini App явно показывайте, какие источники поддерживают поиск, привязку личного аккаунта и отправку. При отсутствии интеграции не добавляйте кнопку отправки в Mini App. OAuth-токены источников храните только в DATA_DIR. Используйте устойчивые идентификаторы источников при сохранении откликов.
- Поиск выдаёт результаты источников по мере готовности. Сохраняйте найденные карточки и прогресс фонового поиска, ведите очередь Groq отдельно от браузерных операций. Отделяйте предварительный рейтинг от оценки Groq и его балла по навыкам. Перед отправкой применяйте оба текущих порога и проверяйте обязательные требования по текущему резюме.
- Для сравнения используйте опубликованные точки офиса или геокодирование адреса по действию владельца. Храните только координаты точки отправления в приватном состоянии. Передавайте координаты дома внешнему маршрутизатору только по явному запросу. Карта вакансий и Groq не получают их. Диапазон по расстоянию обозначайте как ориентир.
- Код в `app/`, точка входа `bot.py`, проверки в `tests/` и `.github/workflows/`, документы в `docs/`. Тестируйте миграции, лимиты, владельца, идемпотентность, внешние ответы и перезапуск. CI использует только mock и фиктивные данные.
- Не коммитьте реальные ключи, .env, резюме, базы, логи, cookies, профили и хранилище браузера. Не передавайте настоящие ключи вне целевого окружения без разрешения. Подключение оплаты и удаление пользовательских данных требуют разрешения.
- Не смешивайте состояние черновика, факт открытия HH и отметку отправки. Любые результаты, проверенные только mock, описывайте соответствующим образом.

## Исторические проблемы

Отсутствие OWNER_ID приводило к KeyError. Скачивание Chromium приводило к OOM 137. Смена entrypoint ломала запуск через отсутствующий install_shell.py. Lightpanda подключалась по CDP, но авторизация и отправка не проверены. Диагностика ранее формально подтверждала вход. Общий RuntimeError скрывал причину сбоя. Предыдущие черновики иногда описывались как отправленные отклики. Сохраняйте один entrypoint, диагностируйте конкретные этапы и проверяйте состояние на уровне реальной функции.
