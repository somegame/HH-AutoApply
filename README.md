# HH AutoApply 6.4.0

Персональный Telegram Mini App для поиска работы на iPhone. Вакансии, сопроводительные письма, история откликов и подключения доступны в одном окне. Основной хостинг — Bothost. [Быстрый старт](docs/QUICK_START_IPHONE.md) · [Состояние проекта](docs/PROJECT_STATE.md)

## Мини-приложение в Telegram

Откройте `/app` в личном чате с ботом. В **Поиске** можно выбрать площадку и включить фильтр **Только с откликом в приложении**. В **Откликах** находятся сохранённые вакансии, черновики, письма и журнал результатов. **Аккаунты** управляют подключениями и профилем для писем. Используются существующие `LOGIN_PUBLIC_URL` и `PORT`. Сервер проверяет подпись данных Mini App и числовой ID владельца. [Telegram Mini Apps](https://core.telegram.org/bots/webapps)

| Источник | Поиск | Подключение и отправка |
| --- | --- | --- |
| HeadHunter | Локальный Chromium, без HH API | Внутри Mini App. Сессия сохраняется сразу после подтверждения личного кабинета или редактируемого резюме. Фоновый поиск доступен сразу после входа. Резюме загружается через список, встроенную карточку HH или ссылку на свою карточку |
| SuperJob | Официальный API с `SUPERJOB_API_KEY` | Официальное окно SuperJob, выбор резюме и отправка из приложения. Для подключения нужен `SUPERJOB_CLIENT_ID` |
| Работа России | Публичный каталог вакансий | Только поиск |
| Хабр Карьера, Авито Работа, Работа.ру | Каталог подключений, карточки можно добавить по ссылке | Подключение аккаунта и отправка в Mini App недоступны |

Отклики HH и SuperJob показываются в одном журнале. После подтверждения площадкой карточка получает статус **Отправка подтверждена площадкой**. Если результат неизвестен, повтор заблокирован. Для HH доступна сверка внутри приложения. Статусы работодателей, например приглашение на собеседование, пока не синхронизируются. Для отправки нужен постоянный Volume, `AUTO_SEND=true` нужен только для автооткликов HH.

Для писем включите обработку профессионального текста резюме в Groq. Карточки с других сайтов сохраняются в журнале по HTTPS-ссылке. Поиск в «Работе России» использует открытый каталог. [Работа России](https://trudvsem.ru/opendata) · [SuperJob API](https://api.superjob.ru/)

### Сравнение вакансий и дорога

В **Поиске** включаются смежные запросы. Приложение объединяет явные дубли, раскладывает рейтинг на пять факторов и выделяет до трёх вакансий с оценкой от 75 и полнотой данных от 60%. Варианты с неподтверждёнными обязательными требованиями не получают отметку лучших. Сравнить можно до трёх карточек. На карте видны опубликованные или найденные по точному адресу точки офиса. [OpenStreetMap](https://www.openstreetmap.org/copyright)

Для сравнения используются соответствие резюме (45), зарплата (20), дорога (20), предпочтительный формат (10) и свежесть (5). Вес отсутствующих показателей уменьшает полноту данных и влияет на порядок. После анализа карточка показывает общий балл Groq, отдельное совпадение по навыкам и раздел «Что предстоит делать» по описанию работодателя. До анализа видны статус очереди и предварительное совпадение по словам в резюме. Зарплата сравнивается с указанным минимумом поиска. Сортировки включают рейтинг, зарплату, дорогу, соответствие и дату публикации.

Поиск показывает карточки по мере ответа площадок. Если одна площадка долго отвечает, другие результаты остаются доступными. Вакансии с описанием сохраняются в SQLite и ждут анализа после закрытия приложения. Фоновый режим HH по сохранённым настройкам проверяет новые публикации и продолжает обработку предыдущих страниц. После временных ошибок он повторяет проверку с увеличением паузы. Истёкший вход и ограничения сайта требуют действий владельца.

В **Аккаунтах** задайте точку отправления и способ передвижения. Можно использовать геопозицию, если Telegram разрешит доступ, или ввести координаты. При указанном лимите поиска диапазон времени сравнивается по верхней границе. Вакансии без данных о дороге можно оставить в выдаче. Домашний адрес не записывается в базу, сохраняются только координаты. Геопозиция не передаётся Groq или в запросах карты вакансий.

Оценка в пути доступна без ключа, если известны обе точки. Это приближённый диапазон по расстоянию для транспорта, машины, велосипеда или ходьбы. На удалённой работе поездка считается необязательной. Опциональный `ORS_API_KEY` включает поиск точки по адресу и расчёт дорожного маршрута по нажатию. Карты получают введённый адрес при поиске точки или координаты начала и конца при запросе маршрута на машине, велосипеде или пешком. В расчёте нет текущих пробок и расписания общественного транспорта. [HeiGIT](https://api.heigit.org/)

### Резюме и автоотклики HH

1. В **Аккаунтах** нажмите **Загрузить резюме**. Если HH не открыл список, нажмите **Найти резюме в HH** и откройте карточку с кнопкой **Редактировать**. Можно также вставить ссылку на своё резюме. Бот проверяет, что оно принадлежит подключённому аккаунту. [Как скопировать ссылку](https://feedback.hh.ru/knowledge-base/article/5899)
2. Разрешите Groq обработку профессионального текста. В Bothost укажите `GROQ_API_KEY`, подтвердите наличие постоянного диска и задайте `PERSISTENT_STORAGE=true` и `AUTO_SEND=true`.
3. В **Аккаунтах → Автоотклики HH** укажите минимальное совпадение по навыкам и нажмите **Сохранить порог**. По умолчанию это 80%. Затем нажмите **Включить автоотклики** и подтвердите режим. Перед отправкой применяются сохранённые поисковые фильтры, общий порог Groq и порог по навыкам. Все обязательные требования должны быть подтверждены. В автоматическом письме приложение использует проверенные выдержки из резюме и названия вакансии и компании.
4. Результат виден во вкладке **Отклики**. Анкеты и неподдерживаемые формы остаются для проверки. При неизвестном результате автоотклики приостанавливаются. Недавние неизменённые черновики из фонового поиска пересматриваются при включении режима.

### Подключение SuperJob

Зарегистрируйте приложение SuperJob, задайте URL возврата `<LOGIN_PUBLIC_URL>/mini/oauth/superjob` и поместите ID и ключ в переменные Bothost. Для действующего домена URL получится `https://hh.bothost.tech/mini/oauth/superjob`. В Mini App откройте **Аккаунты → Подключить SuperJob → Войти на SuperJob**. После согласия на SuperJob вернитесь в Telegram. При наличии нескольких резюме выберите нужное. Ключ приложения и токены владельца хранятся на сервере. [SuperJob API](https://api.superjob.ru/)

## Локальный браузер

1. В настройках Bothost включите Dockerfile из репозитория и веб-интерфейс с HTTPS-доменом. Укажите `BROWSER_ENGINE=chromium`, `LOGIN_PUBLIC_URL=https://<ваш-домен-бота>` и проверьте внутренний порт. Приложение слушает `PORT`, по умолчанию 8000. Telegram остаётся на long polling. [Домены и порты](https://bothost.ru/docs/domains-and-ports)
2. В чате откройте **Меню бота → Войти в HH через браузер** и откройте ссылку с телефона. Коснитесь поля HH и вводите текст с клавиатуры. Страница прокручивается свайпом. Если HH ждёт SMS, появится поле с цифровой клавиатурой. Введите код и нажмите **Ввести код**. После подтверждения входа бот сохранит сессию. Если HH уже показал резюме, бот выведет его в Telegram. Загрузить резюме можно отдельной кнопкой. Кнопка **Проверить вход** в окне запускает повторную проверку и оставляет форму открытой, если вход ещё не подтверждён. Ссылка действует восемь минут. Выберите резюме и разрешите обработку его профессионального текста в Groq.
3. Нажмите **Включить фоновый поиск**. Результаты появятся в журнале Mini App. Для писем выберите резюме и разрешите анализ в Groq. Для автоотправки нужны постоянный Volume, `AUTO_SEND=true` и свежее подтверждение в Telegram. Отправка допускается в форме с проверенной вакансией, точным ID резюме и полем письма. Неизвестный результат ставит цикл на паузу.
4. После перехода старое значение `BROWSER_ENGINE=browserbase` включает ручной режим. Укажите `chromium` для запуска локальной версии. Старый ключ внешнего браузера можно удалить из Bothost.

Chromium ставится при сборке, используется один браузер за раз, операции ограничены по времени. Для ссылки на вход нужен доступный с iPhone HTTPS-домен. Образ занимает около 836 МиБ в распакованном виде локально, доступную квоту диска и RAM проверяйте на своём тарифе. Полный вход на HH с iPhone и реальные отклики ещё предстоит проверить.

## Компоненты

- Python 3.12 и Telegram long polling в одном процессе с точкой входа `bot.py`.
- SQLite в `DATA_DIR`. Версия схемы через `PRAGMA user_version`, WAL, транзакции, индекс очереди и уникальный идентификатор вакансии. Файловая блокировка ограничивает число процессов на одном `DATA_DIR`.
- Groq через HTTP. Очередь анализируется независимо от браузера. Результаты и цитаты проверяются локально. Кэш хранит до 250 ответов. По умолчанию приложение ограничивает новые запросы до 50 попыток в сутки с интервалом не менее 12 секунд. Излишек остаётся в очереди на следующие сутки. Пауза HTTP 429 учитывает числовой `Retry-After`.
- TXT, PDF с текстовым слоем и DOCX до 2 МБ. PDF и DOCX обрабатываются в дочернем процессе с ограничениями времени и памяти. Резюме хранится в SQLite. В локальной разработке можно положить `resume.txt` рядом с точкой входа для первичной загрузки.

## Подготовка Telegram и Groq

1. Создайте бота в официальном [@BotFather](https://t.me/BotFather) командой `/newbot`. Токен внесите только в переменные Bothost.
2. Для `OWNER_ID` нужен числовой ID вашего аккаунта. Если у вас его ещё нет, отправьте сообщение новому боту и получите свой `message.from.id` из ответа метода `getUpdates` официального Bot API до запуска polling. Токен является частью URL метода, поэтому не передавайте ссылку и удалите её из истории браузера, если открывали в Safari. [Telegram Bot API](https://core.telegram.org/bots/api#getupdates)
3. Создайте ключ в [Groq Console](https://console.groq.com/keys). Модель `openai/gpt-oss-120b` есть в каталоге. Команда `/groq` проверяет доступ модели с вашим ключом и выбранной ноды. [Карточка модели](https://console.groq.com/docs/model/openai/gpt-oss-120b)

## Переменные

Переменные процесса имеют приоритет над локальным `.env`. Пример находится в `.env.example`. Настройки из Telegram имеют приоритет над стартовыми параметрами поиска.

| Переменная | Назначение |
| --- | --- |
| `TELEGRAM_TOKEN` | Токен бота. При отсутствии читается `TELEGRAM_BOT_TOKEN` или `BOT_TOKEN` |
| `OWNER_ID` | Числовой Telegram ID владельца, обязателен |
| `GROQ_API_KEY` | Ключ Groq, обязателен для анализа |
| `GROQ_MODEL` | Модель с поддержкой JSON object mode, по умолчанию `openai/gpt-oss-120b` |
| `GROQ_DAILY_LIMIT` | Лимит новых попыток обращения к Groq в сутки, по умолчанию 50, диапазон 1–1000. Учитывайте квоту своего ключа |
| `ORS_API_KEY` | Необязательный ключ HeiGIT для геокодирования и маршрутов по запросу |
| `SUPERJOB_API_KEY` | Ключ приложения SuperJob для поиска и подключения аккаунта |
| `SUPERJOB_CLIENT_ID` | ID приложения SuperJob для OAuth. Для публичного поиска не требуется |
| `DATA_DIR` | Каталог SQLite, локально `./data`, на Bothost обычно `/app/data` |
| `PERSISTENT_STORAGE` | Установите `true` после подтверждения Volume, иначе оставьте `false` |
| `SEARCH_QUERY`, `SEARCH_REGION` | Финансовый менеджер, Москва |
| `MIN_SALARY`, `CURRENCY` | 150000, RUB |
| `MIN_SCORE` | Минимальный общий балл Groq, 80, диапазон 0–100 |
| `MIN_SKILL_SCORE` | Минимальный балл Groq по навыкам для автоотклика, 80, диапазон 1–100. Настраивается в Mini App |
| `DAILY_LIMIT` | До 100 отметок отправленных откликов в день |
| `SEARCH_INTERVAL_MINUTES` | 30 минут между проверками новых результатов по запросу и напоминаниями, диапазон 5–1440 |
| `TIMEZONE` | `Europe/Moscow`, граница суток для статистики и лимитов |
| `LOG_LEVEL` | Уровень логов приложения, по умолчанию INFO |
| `AUTO_SEND` | `false` по умолчанию. Для автооткликов нужны `true`, постоянный Volume и подтверждение в Telegram |
| `BROWSER_ENGINE` | `manual` по умолчанию или `chromium` |
| `LOGIN_PUBLIC_URL` | Домен из панели Bothost или внешний HTTPS-адрес без пути для Mini App и входа HH |
| `PORT` | Внутренний порт сервиса, по умолчанию 8000, на Bothost согласуется с панелью |
| `CHROMIUM_PATH` | Путь к исполняемому файлу, по умолчанию `/usr/bin/chromium-headless-shell` |

## Bothost

Откройте [форму создания бота](https://bothost.ru/create-bot.php), подключите GitHub-репозиторий и выберите `main` после слияния PR. Публичный репозиторий доступен по URL. Для приватного Bothost документирует токены и deploy key. Выберите Dockerfile из корня, чтобы получить Python 3.12 и постоянную команду `python bot.py`. Если тариф предлагает только сборку Python, укажите главным файлом `bot.py`, используйте Python 3.12 из доступных версий и установку из корневого `requirements.txt` при сборке. Сборка Docker использует `/opt/autoapply`, чтобы bind mount в `/app` не перекрывал код. [Документация Bothost](https://bothost.ru/docs/) · [Приватный GitHub](https://bothost.ru/docs/git-repository-access) · [Ветка](https://bothost.ru/docs/repository-branch-deploy) · [Точка входа](https://bothost.ru/docs/main-file-entrypoint)


Заполните токен, ID и ключ Groq в панели и запустите одну реплику. Для Telegram нужен исходящий HTTPS. Браузерный режим также обращается к HH и слушает внутренний веб-порт. Для доступа с iPhone нужен HTTPS через Bothost. [Домены и порты](https://bothost.ru/docs/domains-and-ports)

`DATA_DIR` — папка с настройками, базой вакансий и откликов, резюме и сессией HH. Bothost монтирует постоянный диск в `/app/data` на поддерживаемых тарифах. Проверьте тариф и через файл-менеджер убедитесь, что используемая база находится в `data/autoapply.sqlite3`. Если она уже там, сохраните значение `DATA_DIR=/app/data` и после подтверждения диска задайте `PERSISTENT_STORAGE=true`. Этот флаг служит подтверждением для бота. Если база лежит в другом месте, сначала сделайте резервную копию всей папки с базой и сессией HH. При смене пути бот откроет базу по новому адресу. На временном диске отправка из Mini App недоступна, поскольку при пересборке могут исчезнуть журнал и защита от повторных откликов. [Хранение](https://bothost.ru/docs/database-storage) · [SQLite на Bothost](https://bothost.ru/docs/sqlite-data-lost)

На публичной странице Starter указан как 256 МБ RAM и 0,5 ГБ SSD, Basic как 1 ГБ и 5 ГБ, Pro как 2 ГБ и 15 ГБ. Volume публично заявлен для Basic и Pro. Возможность автодеплоя описана с разными формулировками в списке тарифов и FAQ. Подтвердите разрешения выбранного тарифа и настройте webhook GitHub, если это предусмотрено в панели. Точную квоту и поведение своего экземпляра проверяйте по панели и `/diagnose`. [Тарифы Bothost](https://bothost.ru/) · [Лимиты RAM](https://bothost.ru/docs/bot-memory-timeout-rate-limits)

На временном диске бот предупреждает о потере резюме, настроек и истории. При таком хранилище отклики отправляет владелец вручную. После потери базы сверяйтесь с разделом «Отклики» HH. Для сохранности используйте существующий постоянный том. Если Volume получить невозможно, совместимое внешнее направление — PostgreSQL с отдельным адаптером и миграцией, которых в этой версии нет. Не размещайте SQLite на объектном хранилище. Платные сервисы проект не подключает.

## Работа с телефона

- **✍️ Анализ вручную** → **📄 Резюме для анализа** → **Загрузить / заменить**. Отправьте профессиональный текст без ФИО, контактов и секретов. Проверьте извлечение и отдельно разрешите передачу в Groq. Регулярные выражения убирают типовые контакты, но не определяют все персональные сведения. Письмо и цитаты проверяйте сами.
- **🔑 Проверить вход** открывает ссылки входа и резюме. Введите данные на HH. Увидев своё резюме или профиль, вернитесь в чат и нажмите **➡️ Продолжить**, чтобы перейти к следующему шагу. Выберите подходящее резюме при отклике на HH. Telegram хранит только профессиональный текст для анализа.
- **🔎 Подобрать вакансии** открывает ссылки. Сохраните поиски в самом HH, чтобы получать подборки автоматически. Напоминания в Telegram используют выбранный интервал. Форма поиска заполняет запрос, зарплату и известный регион Москва. Другие регионы, стаж, график и формат выберите в интерфейсе HH. Смежные запросы включаются отдельно.
- Перешлите ссылку на конкретную вакансию или нажмите **Добавить вакансию**. Заполните шаблон. Зарплата задаётся как `150000-200000 RUB`, зарплата без диапазона — `150000 RUB`. Фильтры региона, графика, формата и опыта используют введённые в карточке сведения. Совпадающий ID открывает имеющуюся карточку.
- В режиме подтверждения черновик требует кнопки **Подтвердить черновик**. В ручном режиме черновик сразу готов к переносу. Оценка модели помогает решению, письмо остаётся редактируемым. На вопросы работодателя отвечайте в HH; карточку можно отметить как требующую ответов.
- Откройте вакансию, проверьте прежние отклики, вставьте письмо и отправьте отклик на HH. Когда запись появилась в разделе «Отклики», отметьте её в боте. Если результат неясен, используйте **Результат неизвестен**. Лимит относится к отметкам в SQLite и не ограничивает действия в Safari.
- **Остановить анализ и напоминания** в разделе **🔎 Подобрать вакансии** сохраняет паузу. Подписки HH управляются непосредственно в HH.

## Диагностика и сопровождение

- `/diagnose` покажет RSS, cgroups, свободное место на файловой системе базы, SQLite, очередь и доступность внешних сервисов. Объём свободного места может относиться к файловой системе целиком. Постоянство проверяется повторным деплоем с тестовыми данными. `/errors` показывает последние ошибки анализа. Логи приложения пишутся в stdout, ротация и срок хранения определяются хостингом.
- Ошибка `OWNER_ID` требует числового ID без @. При Telegram Conflict остановите другие экземпляры с тем же токеном и проверьте webhook старой установки. `HTTP 401` требует проверить ключ. При `403` Groq проверьте доступ модели и регион Bothost. При `429` дождитесь окна следующей попытки. При пропавшей базе проверьте монтирование `/app/data`.
- Перед обновлением сделайте резервную копию Volume средствами панели. Развёртывайте протестированное состояние `main` из Git. После обновления проверьте `/status`, очередь и тестовые данные. Для отката выберите прежний коммит или верните изменения коммитом в GitHub. При несовместимой версии схемы восстановите согласованную копию базы, сделанную перед обновлением.
- Локальная разработка на Linux: установите зависимости `pip install -r requirements-dev.txt`, запустите `ruff check .`, `ruff format --check .` и `python -m pytest -q`. Для запуска используйте `python bot.py`. CI использует тестовый транспорт и синтетические данные. Настоящие ключи, резюме и SQLite в Git не добавляются. Ранее опубликованные токены перевыпустите.
