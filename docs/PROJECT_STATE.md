# Текущее состояние

**Версия 6.6.0. Последняя проверка 27.11.2026.** Добавлены вход в другие площадки из хаба, подтверждение профиля Хабр Карьеры и фоновый поиск независимо от HH.

## Архитектура

- Python 3.12, Telegram long polling, один aiohttp-сервер и SQLite WAL. Mini App использует существующий HTTPS-домен Bothost. Приватные маршруты проверяют подпись данных Telegram, срок и OWNER_ID. Сохраняются предыдущие настройки и записи.
- Вход HH встроен в Mini App, использует существующую короткоживущую ссылку и локальный Chromium. Одно резюме автоматически привязывается, если доступен профессиональный текст. Когда список недоступен, можно открыть свою карточку или вставить ссылку. Фоновый поиск доступен после подтверждения входа. Для писем и откликов действуют прежние условия. Состояние браузера остаётся в `DATA_DIR`. HH API не используется.
- SuperJob подключается по официальному OAuth для соискателей. Приложение хранит токены в SQLite, загружает названия резюме, отправляет выбранное резюме с письмом и отображает результат API. Для подключения нужны ID, ключ и зарегистрированный URL возврата.
- «Работа России» и SuperJob поддерживают отдельный фоновый поиск. Он проверяет сохранённые фильтры и пополняет очередь анализа при работающем боте, независимо от HH.
- OAuth Хабр Карьеры подтверждает логин владельца через `users/me`. Работодательские методы не используются. Для Авито Работы, Работа.ру и «Работы России» вход открывается на сайтах. В журнале доступны фильтр источника, карточки по ссылкам, дополнение описаний и ручная отметка. Отправка из Mini App доступна через HH и SuperJob с постоянным Volume.
- Для автоматической отправки HH после подтверждения владельца нужны выполненные фильтры, общий балл Groq и отдельное совпадение по навыкам от заданных порогов, подтверждённые обязательные требования и письмо из точных выдержек из резюме. Изменённые вручную письма исключены из автовыбора.
- Фоновый HH-поиск хранит в SQLite непрочитанные ID и позицию по запросу, проверяет свежую выдачу и продолжает обход предыдущих страниц. Groq работает в отдельном рабочем цикле, очередь сохраняется между перезапусками. После исчерпания дневного лимита новые обращения возобновляются на следующие сутки. При временных сбоях поиск повторяется, истечение входа или явное ограничение HH останавливают браузерный режим.
- Gemini используется с отдельным согласием. Вакансии, письма и редактор резюме используют общий бюджет соответствующего провайдера. Лимиты и паузы сохраняются отдельно. После восстановления приоритет возвращается к Groq. При исчерпании обоих лимитов вакансии остаются в SQLite.
- Редактор использует только профессиональные факты профиля и владельца. Заголовки разделов и полный текст подтверждённых сведений формирует приложение. До восьми релевантных вакансий служат для выбора приоритетов. Черновик хранится отдельно и экспортируется как TXT. Для HH владелец обновляет резюме на площадке и повторно импортирует его.
- Диагностика разделяет анализ, кандидатов на автоотклик, подтверждённые и неопределённые отправки. Недавние записи, отсеянные по прежнему высокому порогу, могут вернуться на анализ после изменения порога.
- Ограничения HH сохраняются с этапом отказа, если известно, какую страницу запросил браузер. Повторная проверка только читает страницу. Владелец заново включает отправку после прохождения проверки.
- Правки навыков и обязанностей готовятся по отдельным записям работы с опорой на точные цитаты. Бот заполняет выбранное поле, владелец сохраняет изменения через HH. Проверка видимых изменений обновляет локальное резюме для анализа.
- Вакансии могут иметь опубликованную точку офиса. Карта загружает тайлы OpenStreetMap по действию владельца. Для поездок доступны локальный диапазон по прямому расстоянию и необязательные дорожные маршруты HeiGIT. Домашний адрес не сохраняется.
- Подтверждение отправки и неизвестный результат видны в журнале. При неизвестном результате повтор блокируется. Прямой сверкой сейчас располагает HH. Информация о решениях работодателей пока не синхронизируется.

## Проверка

- Проверены переключение после HTTP 429, возврат к Groq, независимое согласие Gemini, сохранение очереди, редактор и статусы отправки. Мобильный сценарий прошёл в Chromium. Используются синтетические ответы.
- На публичном домене Bothost `/health` ответил `ok`. JavaScript совпал с версией 6.5.1 после слияния PR #16. Скриншот показывает HTTP 403 на этапе открытия вакансии HH.
- Проверяются одноразовый callback Хабр Карьеры, независимый фоновый поиск, сохранение дополненного описания и журнал. Реальный OAuth Хабр Карьеры требует активированного приложения и ключей владельца. Тесты используют фиктивные данные и не отправляют заявки на реальные сайты.

## Развёртывание

После слияния PR обновите Git-сборку Bothost, откройте `/app` и проверьте версию в **Аккаунтах**. Для Gemini укажите `GEMINI_API_KEY` и дайте отдельное согласие в Mini App. Проверку авторизованного поиска, доступ моделей с ключами владельца и ресурсы тарифа нужно выполнить после выкладки. Реальная тестовая отправка требует отдельного разрешения. [Хранение SQLite на Bothost](https://bothost.ru/docs/sqlite-data-lost)
