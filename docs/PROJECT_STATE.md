# Текущее состояние

**Версия 5.0.0. Последняя проверка 26.11.2026.** Реализован сценарий со штатным автопоиском HH и ручным переносом выбранной вакансии. Развёртывание на Bothost ожидает слияния PR и настройки владельцем.

## Архитектура и состояние

- Один процесс Python 3.12, Telegram long polling, SQLite WAL в `DATA_DIR`, фоновая очередь, приватный OWNER_ID. Python/Docker не устанавливают браузер или Node.js.
- Вакансии вводятся владельцем. Groq выполняет структурированную оценку, готовит черновик и кэширует результат. При неизвестном исходе оператор проверяет раздел «Отклики» на HH. Отметка в SQLite фиксирует сообщение владельца.
- Browserbase опционально проверяет список проектов через HTTPS. Chromium Headless Shell и Lightpanda не нужны для выбранного сценария. Доступность удалённой сессии и авторизации по CDP не тестировалась.
- Для настроек и истории на Bothost нужен постоянный Volume. Публичные условия указывают Starter 256 МБ RAM/0,5 ГБ SSD, Basic 1 ГБ/5 ГБ, Pro 2 ГБ/15 ГБ. Возможности текущей панели и тарифа владельца пока не проверены. [Bothost](https://bothost.ru/)

## Проверка

- Локально пройдены 14 тестов, включая polling через тестовый Bot API, защиту владельца, SQLite и восстановление, дневные ограничения, TXT/DOCX/PDF, кэш, схему Groq, 429 и REST Browserbase через mock.
- Docker собран на Python 3.12 с сертификатом среды, переданным в сборку. Инициализация внутри контейнера измерена примерно в 48 МиБ RSS и 39–40 КиБ для пустой SQLite. Образ около 128 МиБ по Docker image inspect. Локальный rootless Docker не применяет отдельный cgroup-лимит 256 МБ. Пик при работе с документами и использование диска на Bothost не измерялись.
- Реальные Telegram, Groq, Browserbase, деплой Bothost, сохранение Volume между обновлениями и мобильный сценарий HH с аккаунтом владельца предстоит проверить. Настоящие токены и реальные тестовые отклики не использовались.
